# OpenUPI documentation

**Status: specification only. All functionality described in this documentation is planned.**

Start with [Features](FEATURES.md), then [Architecture](ARCHITECTURE.md). Merchant developers should next read [Merchant integration](MERCHANT_INTEGRATION.md). Operators should read [Observers](OBSERVERS.md), [Configuration](CONFIGURATION.md), [Deployment](DEPLOYMENT.md), [Merchant operations](MERCHANT_OPERATIONS.md) and [Operations](OPERATIONS.md).

[Branding](BRANDING.md) defines the OpenUPI identity. [Security](SECURITY.md) defines trust and reliability requirements. [Roadmap](ROADMAP.md) records delivery stages. [Reference](REFERENCE.md) explains the source of the feature scope and differences we must resolve before implementation.

## Documentation conventions

- “Planned” means specified here but unavailable in this repository.
- Tables of ports, configuration names, identifiers and endpoints describe proposed contracts.
- No document is an instruction to install or run an existing OpenUPI product.
- A feature is complete only after implementation, evidence-based validation and a documented status update.
- Future changes must update related contracts and acceptance criteria together.
