# OpenUPI governance

OpenUPI is maintained under the [zyrixdevs GitHub organization](https://github.com/zyrixdevs). This is a maintainer-led project, currently limited to specification and documentation.

## Roles

| Role | Responsibility |
| --- | --- |
| Organization owners | Repository administration, maintainer appointment and licensing authority |
| Maintainers | Scope, reviews, documentation quality and release decisions |
| Contributors | Focused proposals, original work and clear validation |
| Reviewers | Check consistency, risks, usability and attribution |

An issue or pull request does not grant repository access or imply a maintainer appointment.

## Decisions

Small corrections may be reviewed and merged directly. Changes to payment semantics, public contracts, licensing, contribution rights or project scope need a written rationale and maintainer review. Record accepted changes in the relevant documents and changelog.

Implementation stays out of scope until maintainers explicitly open that phase. Feature proposals remain planned until code and evidence exist.

## Reviews and ownership

The organization owns review responsibility through [CODEOWNERS](.github/CODEOWNERS). CODEOWNERS does not itself enable branch protection or require approvals; those are separate repository settings.

Maintainers should avoid merging disputed or sensitive changes without resolving comments. Conflicts of interest in conduct or permission decisions should be disclosed and another uninvolved maintainer involved when available.

## Releases and access

No software release or support guarantee exists yet. Release tags, published packages and maintainership must not be implied by README artwork. New access, license exceptions and official partnerships require an authorized owner decision.

See [CONTRIBUTING.md](CONTRIBUTING.md), [SECURITY.md](SECURITY.md) and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
